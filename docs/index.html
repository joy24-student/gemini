Getting started

Use this path when you need the fastest production setup with minimum confusion.

1Install dependencies

Install the Python package requirements and optional dependencies for FastAPI, Prometheus, voice, or Playwright if your deployment uses those modules.

2Load Gemini credentials

Use auto-cookie extraction or paste __Secure-1PSID and __Secure-1PSIDTS into a secure server-side secret store.

3Launch the gateway

Run the FastAPI service, confirm /health/live and /health/ready, then create API keys for client applications.

4Integrate clients

Point your Python, JavaScript, Go, Rust, PHP, or OpenAI SDK client to the local or hosted gateway base URL.

Request architecture

The gateway separates user experience, routing, authentication, account balancing, and protocol parsing into clear layers.

Client interfaceChat UI, SDK, CLI, or external OpenAI-compatible client.
FastAPI gatewayAuthentication, validation, request normalization, and SSE response formatting.
Cookie poolChooses a healthy Google account and handles failover under rate limits.
Core engineBuilds f.req, injects SNlM0e, and parses wrb.fr envelopes.
Gemini Web RPCHTTP/2 StreamGenerate requests against the Gemini web interface.

Primary strengths

  • No paid AI Studio key required.
  • Streaming and non-streaming interfaces.
  • Can expose a drop-in OpenAI-style API.
  • Supports persistent conversations and multi-user scaling.

Operational cautions

  • Cookies are highly sensitive and must be protected.
  • Unofficial protocols may drift over time.
  • Account pool health monitoring is essential.
  • Production deployments should always use HTTPS and bearer auth.

Authentication model

The system can authenticate in two layers: upstream Gemini access with session cookies, and downstream gateway access with bearer keys.

Upstream authentication

  • __Secure-1PSID identifies the Google session.
  • __Secure-1PSIDTS carries the rotating anti-replay value.
  • Credentials can be auto-extracted from supported browsers.
  • Cookie pools provide load distribution and failover.

Downstream authentication

  • Expose the gateway through bearer keys.
  • Use key labels to separate local, staging, and production consumers.
  • Restrict CORS and origin exposure.
  • Never place sensitive cookies in public frontend code.

Streaming behavior

Streaming is critical for a chat experience that feels fast and modern. The gateway returns incremental assistant output using Server-Sent Events while preserving full-response reconstruction on the client.

Best practice: buffer incomplete SSE frames, merge partial chunks, and only finalize the assistant turn when the stream explicitly ends.

Deployment patterns

You can run the gateway locally for development or deploy it behind a reverse proxy in containerized or serverless environments.

Local development

Run FastAPI directly, store test cookies in environment variables, and use the built-in UI for operations.

Docker or Compose

Package the gateway with dependency isolation and attach volumes or secret providers for secure credential injection.

Reverse proxy + HTTPS

Use NGINX or another proxy to terminate TLS, protect SSE behavior, and add rate limiting or access control.

Observability

The gateway should expose enough telemetry to detect credential failure, high latency, model issues, and protocol drift.

Recommended telemetry

  • Latency distribution for chat completions.
  • Per-account health and failover counts.
  • HTTP status, rate-limits, and auth failures.
  • Ready/live probe state over time.

Operational triggers

  • Spike in 401 or 403 errors.
  • Repeated 429s on the same account.
  • Unexpected empty or malformed model responses.
  • Protocol schema changes requiring parser updates.

Security baseline

Session cookies provide account-level access. Never expose them in client-side logs, source control, screenshots, or public deployments. Run the gateway behind HTTPS, require bearer keys, restrict CORS, rotate credentials, and use secret storage in production.

Troubleshooting

Use this checklist when the gateway behaves unexpectedly.

  • If health probes fail, validate cookie freshness and account accessibility first.
  • If streaming is truncated, inspect network buffering, SSE parsing, and reverse-proxy settings.
  • If requests succeed but models return empty output, capture the raw response envelope and compare it against the expected parser schema.
  • If some accounts fail repeatedly, quarantine them from the pool until credentials are refreshed.
